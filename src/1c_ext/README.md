# Расширение MCP_Сервер

Расширение конфигурации, которое превращает информационную базу 1С (далее — база) в MCP-сервер: AI-ассистент (Claude, Cursor и другие MCP-клиенты) получает доступ к данным и функциям базы.

## Что такое MCP-сервер в 1С

MCP (Model Context Protocol) — протокол, по которому AI-ассистент обращается к внешним системам. Сервер предоставляет ассистенту три вида возможностей:

| Вид | Что это | Пример |
|---|---|---|
| **Инструменты** (tools) | Функции, которые ассистент вызывает сам, когда решает задачу | Получить список объектов метаданных |
| **Ресурсы** (resources) | Документы, которые MCP-клиент передаёт ассистенту как справочный материал | Описание синтаксиса языка 1С |
| **Промпты** (prompts) | Готовые шаблоны запросов, которые пользователь выбирает в MCP-клиенте | Шаблон «проанализируй объект» |

Чаще всего ассистент работает через инструменты: так он читает и обрабатывает данные базы.

Технически MCP-сервер — это HTTP-сервис `mcp_APIBackend` из расширения. Чтобы MCP-клиент мог к нему подключиться, базу публикуют на веб-сервере; после этого HTTP-сервис доступен по адресу вида `http://<веб-сервер>/<имя публикации>/hs/mcp/`.

Все инструменты, ресурсы и промпты базы перечислены в обработке «Управление MCP-сервером» («Все функции» → «Обработки») на вкладках «Инструменты», «Ресурсы» и «Промпты». Права пользователей эти списки не учитывают: что доступно конкретному пользователю, определяют роли (см. раздел «Права доступа»).

## Установка и подключение

1. Загрузить расширение из файла `MCP_Сервер.cfe` (папка `build/` в корне репозитория): в конфигураторе «Конфигурация» → «Расширения конфигурации» или в режиме 1С:Предприятие «Все функции» → «Стандартные» → «Управление расширениями конфигурации». Нужна платформа 8.3.20 или новее.
2. Опубликовать базу на веб-сервере и отметить в публикации HTTP-сервис `mcp_APIBackend`. Адрес MCP-сервера: `http://<веб-сервер>/<имя публикации>/hs/mcp/`.
3. Проверить, что у пользователя, под которым будет работать MCP-клиент, есть доступ (см. раздел «Права доступа»).
4. Подключить MCP-клиент к адресу MCP-сервера. Примеры настроек — в папке [`mcp_client_settings/`](../../mcp_client_settings/).

### Под каким пользователем 1С работает MCP-клиент

При прямом подключении к HTTP-сервису `mcp_APIBackend` недоступны две возможности протокола MCP:

- **OAuth2** — вход, при котором пользователь вводит логин и пароль в браузере;
- **транспорт stdio**, при котором MCP-клиент сам запускает сервер как консольную программу. Некоторые MCP-клиенты поддерживают только его.

Обе проблемы решает Python-прокси ([документация](../py_server/README.md)): он стоит между MCP-клиентом и 1С.

| Подключение | Как задаётся пользователь 1С | Под кем работают MCP-клиенты |
|---|---|---|
| Напрямую, пользователь в публикации (`default.vrd`) | В MCP-клиенте ничего не задаётся | Все под одним пользователем. Просто, но небезопасно: войдёт любой, кто знает адрес |
| Напрямую, Basic-авторизация | Логин и пароль в HTTP-заголовке `Authorization` в настройках MCP-клиента, если клиент умеет передавать заголовки | Каждый под своим |
| Напрямую, токен JWT | Токен в HTTP-заголовке; публикация настроена на приём токенов | Каждый под своим |
| Через прокси, режим stdio | Логин и пароль в настройках MCP-клиента (переменные окружения запуска прокси) | Каждый под своим |
| Через прокси, режим HTTP | Без OAuth2 — в настройках прокси (`.env`). С OAuth2 — вход через браузер | Без OAuth2 — все под одним. С OAuth2 — каждый под своим |

### Работа без веб-сервера

Если опубликовать HTTP-сервис нельзя, через прокси доступны экспериментальные транспорты: обмен файлами в папке (в том числе по FTP) и обратный HTTP. Запросы выполняет обработка «Управление MCP-сервером» (вкладка «MCP без веб-сервера (тест)»), открытая в сеансе 1С, — от имени пользователя этого сеанса. Настройка — в [документации прокси](../py_server/README.md#экспериментальные-транспорты-до-1с-без-веб-сервера). Эти транспорты не предназначены для промышленной эксплуатации.

## Свои инструменты, ресурсы и промпты

Инструменты, ресурсы и промпты описываются в **обработках-контейнерах**. Одна обработка может содержать несколько инструментов.

Обработку можно создать прямо в расширении `MCP_Сервер`, но тогда изменения пропадут при обновлении расширения. Лучше создать её в своём расширении (см. раздел «Компоненты»).

Чтобы добавить инструмент:

1. Создать обработку и включить её в подсистему `mcp_КонтейнерыИнструментов` (вложена в подсистему `mcp_MCPСервер`).
2. В модуле менеджера обработки реализовать два экспортных метода:
   - `ДобавитьИнструменты(Инструменты)` — описывает инструменты: имя, описание, параметры. Для этого есть функции общего модуля `mcp_Метаданные`: `ДобавитьИнструмент`, `ПараметрИнструмента`, `СхемаПараметровИнструмента`;
   - `ВыполнитьИнструмент(ИмяИнструмента, Аргументы)` — выполняет инструмент. `Аргументы` — структура с параметрами вызова. Возвращает строку или массив элементов содержимого.
3. Создать роль с правом «Использование» на обработку и выдать её пользователям (см. раздел «Права доступа»). Для обработки внутри `MCP_Сервер` роль нужна только при выборочном доступе: `mcp_ПолныеПрава` уже даёт право на неё.

Ресурсы и промпты добавляются так же:

| Вид | Подсистема | Методы модуля менеджера |
|---|---|---|
| Ресурс | `mcp_КонтейнерыРесурсов` | `ДобавитьРесурсы(Ресурсы)`, `ПрочитатьРесурс(Адрес)` |
| Промпт | `mcp_КонтейнерыПромптов` | `ДобавитьПромпты(Промпты)`, `ПолучитьПромпт(ИмяПромпта, Параметры)` |

Форма настроек. Если контейнеру инструментов нужна форма настроек, её объявляет необязательный метод `ДобавитьФормыНастроек(Формы)`, внутри него — вызов `mcp_Метаданные.ДобавитьФормуНастроек(Формы, Имя, Заголовок, ПутьКФорме, Порядок)`. Форма появится на вкладке «Настройки» обработки «Управление MCP-сервером». Работает только для контейнеров из подсистемы `mcp_КонтейнерыИнструментов`.

Параметры методов и примеры — в [`agents.md`](agents.md).

## Права доступа

Инструмент доступен пользователю, если у пользователя есть право «Использование» на обработку-контейнер, в которой инструмент описан. То же для ресурсов и промптов. Недоступный инструмент (ресурс, промпт) не показывается в списке, а на попытку его вызвать сервер отвечает, что он не найден.

### Роли расширения

| Роль | Что даёт |
|---|---|
| `mcp_ПолныеПрава` | Все объекты расширения, включая объекты, добавленные позже. Основная роль расширения |
| `mcp_БазоваяРоль` | Только подключение к серверу (HTTP-сервис `mcp_APIBackend`), без инструментов |
| `mcp_ИнструментМетаданные` | Инструменты `list_metadata_objects` и `get_metadata_structure` |
| `mcp_РесурсОписаниеСинтаксиса` | Ресурс с описанием синтаксиса языка 1С |

У каждого компонента — свои роли.

### Свойство «Использовать основные роли для всех пользователей»

Основные роли — роли, перечисленные в одноимённом свойстве расширения. У `MCP_Сервер` основная роль одна: `mcp_ПолныеПрава`.

Свойство «Использовать основные роли для всех пользователей» можно включить или выключить.

- **Включено:** все пользователи получают основные роли расширения автоматически, назначать их не нужно. Для `MCP_Сервер` это значит: всем доступны все инструменты. Исключение — пользователи, которым не назначено ни одной роли: на них основные роли не действуют.
- **Выключено:** пользователь получает только роли, назначенные ему явно.

### Как настроить

**Все пользователи видят все инструменты:** включить свойство у расширения `MCP_Сервер` и у компонентов.

**Пользователи видят разные наборы инструментов:**

1. Выключить свойство у расширения `MCP_Сервер`. У компонентов — тоже, если их инструменты нужно выдавать выборочно.
2. Назначить `mcp_БазоваяРоль` всем, кто подключается к серверу.
3. Назначить роли нужных инструментов из таблицы выше и роли компонентов.

### Как назначать роли

- **Базы на БСП** (Библиотеке стандартных подсистем) — через профили групп доступа: создать профиль с `mcp_БазоваяРоль` и ролями нужных инструментов; создать группу доступа с этим профилем; включить в неё пользователей.
- **Базы без БСП** — программно, в режиме 1С:Предприятие под администратором. В конфигураторе роли расширений в свойствах пользователя не показываются.

```bsl
Пользователь = ПользователиИнформационнойБазы.НайтиПоИмени("<имя пользователя>");
Пользователь.Роли.Добавить(Метаданные.Роли.mcp_БазоваяРоль);
Пользователь.Записать();
```

### Администраторы

Пользователь с конфигурационной ролью «ПолныеПрава» видит все инструменты всех расширений независимо от ролей расширения. Это поведение платформы (с версии 8.3.14).

В базах на БСП роль `mcp_ПолныеПрава` автоматически попадает в профиль «Администратор»: БСП включает в этот профиль все роли расширений, имена которых оканчиваются на «ПолныеПрава».

## Компоненты

**Компонент** — отдельное расширение со своими инструментами. Основное расширение изменять не нужно: при запуске сеанса оно само находит компоненты. В компоненты выносят инструменты, которые нужны не везде или которым требуются свои таблицы в базе (регистры, справочники). Само основное расширение таблиц не содержит и устанавливается без реструктуризации базы.

### Управление компонентами

На вкладке «Компоненты» обработки «Управление MCP-сервером» — список компонентов с версиями и состоянием и кнопки «Установить», «Обновить», «Включить», «Отключить», «Проверить». Компонент начинает работать в новых сеансах; текущий сеанс после установки или включения нужно перезапустить.

Чтобы кнопки работали, у расширения `MCP_Сервер` должен быть снят флаг «Безопасный режим». Для работы самого MCP-сервера это не требуется.

При установке кнопкой у компонента включается свойство «Использовать основные роли для всех пользователей»: его инструменты сразу доступны всем. Чтобы выдавать их выборочно, выключите свойство (см. раздел «Права доступа»).

В списке два вида компонентов:

- **поставляемые** — входят в сборку основного расширения, устанавливаются кнопкой «Установить». В сборке из этого репозитория поставляемых компонентов нет;
- **сторонние** — расширения, загруженные в базу вручную. Отображаются в списке, только пока включены. Отключённый сторонний компонент включается флагом «Активно» в списке расширений конфигурации.

Настройки компонентов — на вкладке «Настройки».

### Как сделать свой компонент

1. Создать расширение.
2. Добавить корневую подсистему, имя которой содержит `mcp_MCPСервер`, например `МОЙ_mcp_MCPСервер`.
3. Добавить в неё подсистемы с точными именами `mcp_КонтейнерыИнструментов`, `mcp_КонтейнерыРесурсов`, `mcp_КонтейнерыПромптов` (только нужные).
4. Добавить обработки-контейнеры, как описано в разделе «Свои инструменты, ресурсы и промпты».
5. Создать в расширении роль с правом «Использование» на свои обработки-контейнеры.

Если в расширении нет ни одной роли, платформа открывает его объекты всем пользователям, и выдавать инструменты выборочно не получится.
