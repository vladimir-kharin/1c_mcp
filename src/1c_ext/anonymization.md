# Обезличивание данных

С версии 1.10.0 в расширении есть подсистема обезличивания. Её задача — не отправлять персональные данные и секреты
базы в облачную языковую модель.

**Сама подсистема ничего не обезличивает.** В базовом расширении нет инструментов, которые выдают данные базы:
инструменты метаданных и ресурс синтаксиса данных не касаются. Подсистема даёт возможности: настройки базы, правила,
преобразование значений, скрытие неготовых инструментов. Чтобы данные закрывались, их должен учитывать ваш инструмент.
Как это сделать — ниже.

Готовое решение на этой подсистеме — [Multitool MCP для 1С](https://vharin.ru/info/1c_multitool_mcp/): запросы
и журнал регистрации с обезличиванием.

Механизм разработал Михаил Настасков ([GitHub](https://github.com/mr-ske1r)).

## Что видит администратор

Вкладка «Обезличивание» обработки «Управление MCP-сервером». Видна пользователю с правом «Администрирование».

- **Флажок «Обезличивать данные, передаваемые агенту».** По умолчанию выключен, и тогда подсистема ни на что не влияет.
  Обезличивание — свойство базы, а не пользователя: ролей нет.
- **Правила** — что закрыть: объект метаданных целиком (`Справочник.Контрагенты`), табличную часть
  (`Справочник.Партнеры.КонтактнаяИнформация`) или поле (`Справочник.Контрагенты.ИНН`,
  `РегистрНакопления.Продажи.Сумма`). Всё, на что правил нет, открыто. Правила подбираются по дереву метаданных
  или заполняются по признакам персональных данных и секретов (меню «Заполнить»). Включить обезличивание без
  единого правила нельзя: закрывать нечего.
- **Смена ключа.** Токены и метки строятся на ключе базы. После смены старые токены и метки перестают совпадать с новыми.
- **«Обезличивание в инструментах»** — список форм собственных настроек инструментов (см. ниже).

Настройки, правила и ключ хранятся в хранилище общих настроек: новых объектов метаданных и реструктуризации нет.
Изменения действуют в новых сеансах. HTTP-сервис держит сеанс, пока к нему обращаются, поэтому после записи
настроек нужна пауза в запросах.

## Что делает подсистема сама

**Скрывает неготовые инструменты.** При включённом обезличивании агент видит только инструменты, ресурсы и промпты
с признаком `ДоступенПриОбезличивании`. Остальные скрыты из списка и не вызываются: вызов скрытого инструмента
неотличим от вызова несуществующего. Так новый инструмент не выдаст данные, пока его автор не встроил обезличивание.

**Скрывает текст внутренних ошибок.** Текст ошибки бывает со значением из базы. При включённом обезличивании агент
получает фиксированный текст, а полный пишется в журнал регистрации (событие «MCP.Обезличивание»).

## Признак ДоступенПриОбезличивании

Последний параметр `mcp_Метаданные.ДобавитьИнструмент`, `ДобавитьРесурс`, `ДобавитьПромпт`. По умолчанию `Ложь`.

Ставьте `Истина`, если инструмент:
- данных базы не выдаёт (метаданные, справка, служебные сведения), или
- выдаёт их, но сам обезличивает — по правилам и функциям ниже.

```bsl
mcp_Метаданные.ДобавитьИнструмент(Инструменты, "my_tool", Описание, СхемаПараметров,
	Истина); // ДоступенПриОбезличивании
```

Инструмент, который выполняет произвольный код или читает хранилища настроек, признак не ставит: его ответ
не обезличить.

## Как выглядят закрытые данные

| Значение | Что получает агент |
|---|---|
| Ссылка на объект с правилом (любым: на объект, табличную часть, поле) | токен `Справочник.Контрагенты·<32 hex>`; токен можно вернуть в следующем вызове, инструмент превратит его в ссылку |
| Ссылка в закрытой колонке | токен |
| Строка в закрытой колонке | метка `~…`: одинаковые строки дают одинаковые метки, их можно сравнивать и группировать |
| Число, дата, булево в закрытой колонке | `null` |
| Значение типа, который не выдаётся (хранилище значения и т. п.) | `null` |
| Null, Неопределено, перечисление | как есть |

Что именно считать «колонкой» и что в ней закрыто, решает инструмент: правила по метаданным — универсальная часть
настроек, каждый инструмент применяет их к своим данным сам. Например, инструмент запросов сопоставляет поля
запроса с полями метаданных, а журнал регистрации — объект события с правилами.

## Общий модуль mcp_Обезличивание

Основное — в области «Программный интерфейс». Полные описания параметров — в комментариях модуля.

**Включено ли и что закрыто**

| Функция | Что делает |
|---|---|
| `Включено()` | включено ли обезличивание; кешируется на сеанс |
| `НовыйКонтекст()` | контекст одного вызова инструмента: настройки сеанса и кеши токенов и меток. Создавайте только при включённом обезличивании |
| `ПолеЗакрыто(Объект, ПолеПравила, Контекст, Причина)` | закрыто ли поле: правилом на объект, табличную часть или само поле. В `Причина` — «закрыто правилом …» |
| `ПравилаОбъектов(Объекты)`, `ЕстьПравила(Объекты)` | правила, которые касаются типа, составного типа, объекта или реквизита метаданных, полного имени или массива из них |
| `ОписаниеТаблицы(ИмяТаблицы)`, `ПолеТаблицы(Таблица, ИмяПоля)` | помогают сопоставить таблицу и поле запроса с объектом и полем в правилах |

**Преобразование значений**

| Функция | Что делает |
|---|---|
| `ОбезличенноеЗначение(Значение, КолонкаЗакрыта, Контекст)` | значение для выдачи: токен, метка, `null` или как есть |
| `ОбезличенноеЗначениеДанных(Значение, Контекст, Закрыто)` | то же для структур, соответствий, массивов и таблиц значений, по вложенным значениям |
| `КолонкаТребуетОбработки(ТипЗначения, КолонкаЗакрыта, Контекст)` | изменит ли обезличивание хоть одно значение колонки с таким типом; если нет — колонку можно не обходить |
| `ЗаменитьКолонку(Таблица, Колонка, Значения)` | заменяет значения колонки таблицы значений, сохраняя имя и позицию: токены и метки — строки |
| `ПричинаЗаменыОткрытыхЗначений(ТипЗначения, Контекст)` | текст для агента: что заменено в открытой колонке (ссылки на объекты с правилами) |
| `СсылкаПоТокену(Токен, Контекст)` | ссылка из токена, который агент передал в аргументах; `Неопределено`, если это не токен |
| `ТекстОшибкиДляВыдачи(ИсходныйТекст)` | текст ошибки для агента: при включённом обезличивании — фиксированный, полный — в журнал |

**Собственные настройки инструмента**

| Функция | Что делает |
|---|---|
| `НастройкаИнструмента(Имя, ПоУмолчанию)` | значение настройки инструмента; кешируется на сеанс; при выключенном обезличивании — значение по умолчанию |
| `ХранимаяНастройкаИнструмента(Имя, ПоУмолчанию)` | то же без кеша, для формы настроек; нужно право «Администрирование» |
| `ЗаписатьНастройкуИнструмента(Имя, Значение)` | записывает настройку (строка, число, булево, дата); нужно право «Администрирование» |

## Как встроить обезличивание в свой инструмент

Пример — инструмент выдаёт таблицу из запроса к справочнику.

**1. Описание для агента.** Если обезличивание включено, объясните в описании инструмента, что значат токены,
метки и `null` в его ответе. Описания собираются один раз на сеанс, как и настройки, поэтому проверка здесь корректна.

```bsl
Процедура ДобавитьИнструменты(Инструменты) Экспорт

	Описание = "Список контрагентов: ссылка, наименование, ИНН.";
	Если mcp_Обезличивание.Включено() Тогда
		Описание = Описание + " Включено обезличивание: закрытые строки приходят метками ~..., ссылки - токенами"
			+ " <ПолноеИмя>·<код> (токен можно передать в параметр counterparty), числа и даты - null.";
	КонецЕсли;
	mcp_Метаданные.ДобавитьИнструмент(Инструменты, "list_counterparties", Описание, СхемаПараметров(),
		Истина); // ДоступенПриОбезличивании: инструмент обезличивает сам

КонецПроцедуры
```

**2. Аргументы.** Агент может прислать токен вместо ссылки — превратите его обратно.

```bsl
	Если mcp_Обезличивание.Включено() Тогда
		Контекст = mcp_Обезличивание.НовыйКонтекст();
		Ссылка = mcp_Обезличивание.СсылкаПоТокену(Аргументы.counterparty, Контекст);
	КонецЕсли;
```

**3. Результат.** Для каждой колонки решите, закрыта ли она, и замените значения.

```bsl
Процедура ОбезличитьТаблицу(Таблица, ПолноеИмяОбъекта)

	Если НЕ mcp_Обезличивание.Включено() Тогда
		Возврат;
	КонецЕсли;
	Контекст = mcp_Обезличивание.НовыйКонтекст();

	// ЗаменитьКолонку меняет состав колонок, поэтому обходим по сохраненным именам
	ИменаКолонок = Новый Массив;
	Для Каждого Колонка Из Таблица.Колонки Цикл
		ИменаКолонок.Добавить(Колонка.Имя);
	КонецЦикла;

	Для Каждого ИмяКолонки Из ИменаКолонок Цикл
		Колонка = Таблица.Колонки.Найти(ИмяКолонки);
		Закрыта = mcp_Обезличивание.ПолеЗакрыто(ПолноеИмяОбъекта, ИмяКолонки, Контекст);
		Если НЕ mcp_Обезличивание.КолонкаТребуетОбработки(Колонка.ТипЗначения, Закрыта, Контекст) Тогда
			Продолжить;
		КонецЕсли;
		Значения = Новый Массив;
		Для Каждого СтрокаТаблицы Из Таблица Цикл
			Значения.Добавить(mcp_Обезличивание.ОбезличенноеЗначение(СтрокаТаблицы[ИмяКолонки], Закрыта, Контекст));
		КонецЦикла;
		mcp_Обезличивание.ЗаменитьКолонку(Таблица, Колонка, Значения);
	КонецЦикла;

КонецПроцедуры
```

Если источник колонки определить нельзя (вычисляемое выражение, данные из другого места), считайте её закрытой:
лучше не выдать, чем выдать лишнее. Хорошо, если в ответе вы перечислите закрытые колонки с причиной — агент
поймёт, почему данные скрыты, и сможет переформулировать запрос.

**4. Ошибки.** Текст исключения пропускайте через `ТекстОшибкиДляВыдачи`.

```bsl
	Исключение
		Возврат mcp_Содержимое.ТекстовоеСодержимое(
			mcp_Обезличивание.ТекстОшибкиДляВыдачи(ОписаниеОшибки()));
	КонецПопытки;
```

## Своя настройка обезличивания и её форма

Если правил по метаданным инструменту мало (например, журналу регистрации нужен уровень: строгое, сбалансированное,
без обезличивания), храните свою настройку через `ЗаписатьНастройкуИнструмента` и читайте через
`НастройкаИнструмента`. Имя настройки должно быть уникальным среди инструментов — например, с именем обработки:
`"мой_Контейнер.Уровень"`.

Форма для неё появится в списке «Обезличивание в инструментах»:

1. Включите обработку с формой в подсистему `mcp_ОбработкиСФормойНастроек` (в своём расширении — в подчинённую
   подсистему с этим точным именем внутри корневой подсистемы `…mcp_MCPСервер…`).
2. В модуле менеджера обработки зарегистрируйте форму с разделом `"Обезличивание"`:

```bsl
Процедура ДобавитьФормыНастроек(Формы) Экспорт

	mcp_Метаданные.ДобавитьФормуНастроек(Формы, "мой_Контейнер.Обезличивание", "Мой инструмент",
		"Обработка.мой_Контейнер.Форма.НастройкаОбезличивания", 10, "Обезличивание");

КонецПроцедуры
```

Форма читает значение через `ХранимаяНастройкаИнструмента` и записывает через `ЗаписатьНастройкуИнструмента`.

## Граница защиты

Обезличивание защищает от случайной утечки, а не от намеренного выведывания. Агент может ставить условия
по закрытым полям (иначе не выполнить просьбу «найди заказы Иванова») и по ответам догадываться о значениях.
Свободный текст (комментарии, назначения платежа) закрывается только правилом на поле целиком: маскировки
по шаблону внутри строки нет.

Требования к платформе прежние — 8.3.20 и новее: функции шифрования и хеширования, которые использует подсистема,
есть с 8.3.10.
